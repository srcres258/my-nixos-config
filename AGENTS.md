# AGENTS.md

Personal NixOS / Home Manager flake. Only repo-specific facts an agent would likely miss.

## Repo map

- `flake.nix` is the entrypoint. Outputs:
  - NixOS hosts: `srcres-desktop`, `srcres-laptop`, `srcres-desktop-x99`, `srcres-wsl` (all `x86_64-linux`) and `srcres-orange-pi` (`aarch64-linux`).
  - Home Manager: `homeConfigurations."srcres@<host>"`.
  - Dev shell: `packages.${system}.srcres` (uses `home/develop.nix`, **no** graphical modules).
- `configuration.nix` (repo root) is the shared NixOS base (user, timezone, fonts, nix settings, base services). It does NOT import any host or platform modules itself.
- Per-host layering for NixOS: `./configuration.nix` + `platforms/<platform>/configuration.nix` + `devices/<host>/configuration.nix`.
- Per-host layering for Home Manager: `./home` + `platforms/<platform>/home` + `devices/<host>/home`.
- Home split:
  - `home/pure/` = cross-platform user tools (fish, neovim, opencode, git, gh, fzf, ripgrep, eza, fonts, etc.).
  - `home/system/` = GUI/desktop-only (kitty, firefox, fcitx5, waybar, qutebrowser, kde apps). Only loaded when the host has a graphical session.
  - `home/develop.nix` = minimal pure-only profile used for the `packages.srcres` dev env (no `home/system`).
  - WSL is the exception: `mkPureHomeConfig` in `flake.nix` skips `./home` and loads only `./home/pure` (no `home/system`, no platform home).
- OpenCode config is generated by `home/pure/opencode.nix` into `xdg.configFile."opencode/opencode.json"` and a sibling `oh-my-openagent.jsonc`. Do **not** use `programs.opencode.settings` — there is a known bug with the `settings` option (see comment in that file). Do not touch generated files under `~/.config/opencode/`.
- `modules/virtualization/windows-vm/*` referenced by README no longer exist locally (removed in commit `b2313fa`); README is stale. Ignore any `vmctl` instructions.

## Commands

Run from repo root.

- Verify flake (fast): `nix flake check --no-build` — catches option/type errors without building derivations. Run this first.
- Verify flake (full): `nix flake check`.
- Build a system: `nix build .#nixosConfigurations.<host>.config.system.build.toplevel`.
- Build a home: `nix build .#homeConfigurations."srcres@<host>".activationPackage`.
- Build the dev env: `nix build .#srcres`.
- Update a single legacy-pinned input: `nix flake lock --update-input <name>` (preferred over `nix flake update`).
- Format touched Nix files: `nixpkgs-fmt`.

## Gotchas

- No CI, no pre-commit, no task runner. `nix flake check` is the source of truth.
- `home/default.nix` imports NUR and fetches `srcres258/nur-packages` via `builtins.fetchTarball` on every build → first build needs network and is slow.
- `SRCRES_PASSWORD` env var is the initial password for `users.users.srcres` (set in `configuration.nix` via `mkNixOSConfig`'s `specialArgs`). Empty/lack of it leaves the account locked.
- `hardware-configuration.nix` files are generated by `nixos-generate-config`; do not hand-edit. The `Do not modify this file!` header is real.
- `system.stateVersion` / `home.stateVersion` are per-host and per-home; do not bump casually. Current values: `srcres-desktop` = `25.05` system / `25.05` home, `srcres-wsl` = `25.11` / `25.05`, `srcres-laptop` = `25.11` / `25.05`, `srcres-desktop-x99` = `25.11` / (inherits), `srcres-orange-pi` = `25.11` / `25.11`, `packages.srcres` = `25.11`.
- Orange Pi 5 (RK3588s) specifics in `devices/srcres-orange-pi/configuration.nix`:
  - Out-of-tree `aic8800d80` Wi-Fi driver + firmware built via `fetchFromGitHub` (pinned commit + sha256).
  - Initrd workarounds: forced `boot.initrd.availableKernelModules` / `kernelModules`, a custom `nvme-rescan` systemd service that loops PCIe rescans for ~45s, and an `ensure-sysroot-run` service to create `/sysroot/run` before bind mount. Do not "clean these up" without keeping them — RK3588S PCIe/NVMe link comes up late.
  - `hardware.firmwareCompression = "none"` is required because the AICSemi driver does not resolve NixOS-compressed `.zst` firmware.
  - `boot.kernelPackages = pkgs.linuxPackages_latest` (NOT `linux_zen`).
- Native desktops use `boot.loader.systemd-boot`, `boot.kernelPackages = pkgs.linuxKernel.packages.linux_zen`, `boot.binfmt.emulatedSystems = [ "aarch64-linux" "riscv64-linux" ]`.
- WSL host imports `nixos-wsl.nixosModules.default`; WSL config is in `devices/srcres-wsl/configuration.nix`.
- Login stack: `services.greetd` + `tuigreet` (no DisplayManager). Wayland compositors: `programs.niri.enable = true` in base; `programs.river-classic` (overrides `pkgs.river`) in native. Audio: `services.pipewire` with pulse + alsa. X11 forwarded via `xwayland-satellite`.
- `nix.channel.enable = false` — flakes only.
- Substituters / trusted-public-keys: Tsinghua + USTC mirrors (`nix.settings.substituters`), plus `https://yazi.cachix.org` (`nix.settings.extra-substituters`). `trusted-users` includes `root` and `srcres`.
- `users.users.srcres` extra groups: `wheel networkmanager audio video render docker wireshark i2c input`. Shell is `pkgs.fish`.
- `home/develop.nix` is loaded **only** for the dev env, not for any host. `packages.srcres` will not pick up changes to `home/system/` or platform/device home modules.
- The `modules/virtualization/windows-vm/*` paths in the README no longer exist locally. Do not try to find or rebuild them.
- Ignore `result/`, `result-*`, and `out/` (already in `.gitignore`).

## Style

- Nix: 4-space indent, comma-first function args, `let … in …`, `imports = [ … ]` last.
- Prefer `lib.mkDefault`, `lib.mkForce`, `lib.mkAfter` over ad hoc overrides. The Orange Pi initrd config uses these heavily — match that style when extending it.
- Keep embedded shell snippets idempotent (safe to re-run after a rebuild).
